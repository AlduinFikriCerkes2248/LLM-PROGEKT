### [№ 02] Google AI Studio
**Категорія:** Первинний запит (Крок 6 — Заготовка 1: Інвентаризація відмов від моделі)  
**Інструмент:** Google AI Studio (Gemini 2.5 Flash)  

**Запит:**
> [№ 02]
> Ось моя функція на базі мовної моделі: сервіс спортивної аналітики футбольних матчів Matchday. Користувач надсилає тактичний фокус у форму на сторінці `/leagues/[id]`, застосунок бере з бази назви команд і викликає Gemini API через `askModel`. Відповідь моделі розбирається з JSON і записується в рядок матчу в таблиці `matches` (поле `venue`). Застосунок розгортається на Vercel Hobby (таймаут 300 с).
> 
> Перелічи, що зламається в цій наївній версії. Включи обов'язково 6 категорій:
> 1. Невалідний формат відповіді
> 2. Перевищення лімітів (Rate Limit)
> 3. Недоступність сервісу (503 / збій мережі)
> 4. Зловмисний ввід (Prompt Injection)
> 5. Надто довгий ввід
> 6. Перевищення часу очікування (таймаут)
> Формат: таблиця з колонками «Відмова», «Що станеться в коді», «Що побачить користувач».

**Відповідь моделі:**
> Складено перелік відмов для безсерверного середовища Vercel:
> 1. Невалідний JSON -> `JSON.parse` викине `SyntaxError`, падіння сервера 500.
> 2. Ліміти -> 429 Too Many Requests, блокування API ключа на добу.
> 3. Недоступність сервісу -> необроблений `fetch error`, відсутність запису.
> 4. Зловмисний ввід -> модель виконає команди зловмисника, спотворення бази.
> 5. Довгий ввід -> помилка перевищення токенів контексту.
> 6. Зависання -> функція Vercel зависне і впаде після таймауту платформи.
