# Зв'язки

| Таблиця А | Таблиця Б | Тип зв'язку (1:N / M:N / 1:1) | Як зроблено (поле чи таблиця зв'язку) | Чому саме такий (одне речення) |
| :--- | :--- | :---: | :--- | :--- |
| `leagues` | `profiles` | M:N | Таблиця зв'язку `league_members` (`league_id`, `user_id`) | Один користувач може грати у багатьох турнірних лігах, а в одній лізі змагається багато учасників. |
| `leagues` | `profiles` (owner) | 1:N | Поле `leagues.owner_id` references `profiles.id` | Один користувач-організатор може створити декілька турнірних ліг, але в кожної ліги рівно один творець. |
| `leagues` | `matches` | 1:N | Поле `matches.league_id` references `leagues.id` | У кожній лізі проводиться серія поєдинків, але конкретний матч належить тільки одній турнірній лізі. |
| `matches` | `predictions` | 1:N | Поле `predictions.match_id` references `matches.id` | На один матч роблять прогнози багато учасників, а прогноз прив'язаний до конкретного поєдинку. |
| `profiles` | `predictions` | 1:N | Поле `predictions.user_id` references `profiles.id` | Користувач залишає прогнози на різні матчі туру, і кожен прогноз належить одному автору. |

### Видалені поля
| Таблиця | Поле | Чому, на мою думку, модель його додала |
| :--- | :--- | :--- |
| `profiles` | `bio` | Модель схильна додавати стандартні атрибути соцмереж до кожної таблиці профілю. |
| `profiles` | `avatar_url` | Модель запропонувала поле для медіа-файлів, хоча завантаження зображень відкладено. |
| `leagues` | `description` | Запропоновано шаблонне текстове поле опису, яке не відображається в картках ліг. |
| `leagues` | `max_participants`| Модель припустила наявність ліміту слотів, що не вимагається специфікацією. |
| `matches` | `referee` | Модель згенерувала типові футбольні метадані, які не несуть цінності для студентського заліку. |
| `predictions` | `bet_amount` | Модель за звичкою додала суму ставки, проігнорувавши заборону азартних механік. |
