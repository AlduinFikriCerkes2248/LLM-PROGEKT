# 🏆 Matchday · Платформа спортивних прогнозів та змагальних ліг

Сучасна освітньо-змагальна веб-платформа для організації ліг спортивних прогнозів, турнірів та інтерактивних міні-ігор з віртуальною ігровою економікою. 

Проєкт розроблено як повноцінне рішення для показу освітнім компаніям та партнерам: демонстрація поєднання найсучаснішого веб-стеку з багаторівневою архітектурою кібербезпеки та транзакційною надійністю.

---

## 🚀 Технологічний стек

* **Frontend:** [Next.js 16](https://nextjs.org/) (App Router, Turbopack, React 19)
* **Мова розробки:** [TypeScript 5](https://www.typescriptlang.org/) (сувора типізація)
* **Стилізація:** [Tailwind CSS 3](https://tailwindcss.com/) (темна кібер-стилістика, дизайн-система термінального спорту)
* **Backend & База даних:** [Supabase](https://supabase.com/) (PostgreSQL 15)
  * Row Level Security (RLS) політики
  * Хранимий процедурний код PL/pgSQL
  * Автентифікація Supabase Auth
* **Інструменти якості коду:** ESLint 9 з правилами React Hooks & Next.js

## 🛠️ Як запустити локально

### 1. Клонування та встановлення залежностей
```bash
git clone https://github.com/AlduinFikriCerkes2248/LLM-PROGEKT.git
cd LLM-PROGEKT
npm ci
```

### 2. Налаштування змінних оточення
Створіть файл `.env.local` (за зразком `.env.example`):
```env
NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key

# Прапорець для демонстраційного показу партнерам (true/false)
NEXT_PUBLIC_DEMO_MODE=true
```

### 3. Запуск у режимі розробки
```bash
npm run dev
```
Відкрийте [http://localhost:3000](http://localhost:3000) у браузері.

### 4. Збірка та лінтинг
```bash
npm run lint   # Перевірка ESLint (без помилок)
npm run build  # Повна оптимізована production-збірка Next.js
```

## 🎮 Реалізований функціонал

1. **Ліги та соціальні прогнози (`/leagues`, `/leagues/[id]`):**
   * Створення власних приватних ліг з унікальними інвайт-кодами.
   * Додавання матчів творцем ліги, календар та статуси (заплановано / завершено).
   * Прогнози точного рахунку користувачами з автоматичним нарахуванням балів (3 бали за точний рахунок, 1 бал за вгадану різницю/результат).
   * Тоталізатор та пули ставок на перемогу господарів, нічию або гостей (`home/draw/away`).
   * Таблиця лідерів ліги з динамічним сортуванням.

2. **Одиночні міні-ігри:**
   * **Блекджек проти дилера (`/blackjack`):** класичні правила гри (Hit, Stand, Double, Split, Страхування), розрахунок очок за правилами Лас-Вегасу, 10 рівнів досвіду агента, квести «Lucky Streak», збереження прогресу.
   * **Колесо фортуни (`/wheel`):** векторне SVG-колесо з фізичною анімацією обертання, щоденний ліміт 1 раз на добу, гарантовані бонуси.
   * **Кості (`/dice`):** швидка гра у кубики з таблицею глобального лідерборду.

3. **Система кейсів та винагород (`/cases`):**
   * Щоденний безкоштовний кейс («Кейс 1»).
   * Рідкісні та джекпот-кейси («Кейс 2», «Кейс 3») за внутрішні бонуси.

4. **Онлайн PvP-дуелі (`/online`):**
   * Покрокові поєдинки в Блекджек та Кості між реальними користувачами або тренувальними ботами («PRO-бот», «VIP-бот», «Бот 1»).
   * Автоматичне списання та виплата банку переможцю.

5. **Автентифікація та патріотичний вхід (`/login`):**
   * Вхід та реєстрація через Supabase Auth.
   * Інтро-анімація тризуба та орнаменту на чистих SVG та CSS зі `stroke-dasharray`, підтримка `prefers-reduced-motion` та пропуск кліком.

## 🛡️ Архітектура безпеки (Security First)

У проєкті впроваджено промислові стандарти безпеки веб-додатків із фінансовими/ігровими механіками:

* **Повна ізоляція клієнта від прямих мутацій (RLS):**
  Клієнтський код не має дозволу на прямі виклики `.update()` чи `.upsert()` до балансів користувача (`coins`, баланс додаткової валюти), статусів дуелей чи виплат. Всі операції проходять виключно через SQL-функції.
* **Функції `SECURITY DEFINER` із фіксованим `SET search_path = public`:**
  Запобігає атакам підміни схеми пошуку функцій у PostgreSQL. Кожна дія верифікує `auth.uid() = auth.uid()`.
* **Атомарність та захист від подвійних витрат (`FOR UPDATE`):**
  Усі грошові операції блокують відповідний рядок у таблиці `profiles` або `pvp_duels` через `SELECT ... FOR UPDATE`, що унеможливлює стан гонки (race conditions) при відкритті сайту у двох вкладках чи повторному кліку.
* **Маскування прихованих даних (Fog of War):**
  Функція `pvp_view` фізично не повертає колоду (`deck`) та закриті карти суперника доти, доки матч не завершено (`status = 'completed'`). Прямий `SELECT` колонок закритих карт для ролей `authenticated` відкликано (`REVOKE SELECT`).
* **Серверні таймаути неактивності (`claim_duel_timeout`):**
  Якщо суперник покинув гру або закрив вкладку понад 60 секунд тому (відстежується за серверним полем `last_move_at`), другий гравець може в один клік забрати технічну перемогу й виплату.
* **Серверні кулдауни:**
  Перевірка ліміту відкриття кейсів (1 раз на 24 години) реалізована на рівні сервера в полі `profiles.last_box_at`, що унеможливлює накрутку через очищення `localStorage`.

## 🔒 Демо-режим (`NEXT_PUBLIC_DEMO_MODE=true`)

Спеціально для презентацій освітнім партнерам передбачено демонстраційний прапорець:
* Коли значення `true`:
  * Розділи відкриття кейсів (`/cases`) та PvP-дуелей (`/online`) переводяться в режим чесної заглушки («Недоступно в демо-версії») без виклику будь-яких RPC до бази.
  * Блекджек, колесо, ліги, прогнози та ставки на матчі залишаються повністю активними з інформаційною плашкою: *«Віртуальні монети, без реальних грошей»*.
* Коли значення `false` або не вказано: вся система функціонує у повному бойовому режимі.

## 📌 Відомі обмеження та подальший розвиток

* **Синхронізація онлайн-столів:** Наразі синхронізація кроків у PvP базується на RPC `pvp_view` та періодичному опитуванні. Наступним етапом планується переведення на `supabase.channel()` Realtime Broadcast для мілісекундної реакції.
* **Спортивні дані:** Розклад та результати матчів вносяться організатором ліги вручну або автоматично синхронізуються через Edge Function `sync-results` за наявності `external_id` матчу.

## 🔑 Налаштування секретів для Edge Function (Авторезультати)

Автоматична синхронізація результатів матчів реалізована через безпечну серверну **Edge Function** (`supabase/functions/sync-results`), яка викликає функцію бази даних `apply_auto_result` із правами `service_role`.

> [!IMPORTANT]
> **API-ключ провайдера спортивних даних ніколи не потрапляє у клієнтський код (`NEXT_PUBLIC_*`), браузер або git-репозиторій.** Він зберігається виключно у зашифрованому сховищі секретів Supabase (Vault / Edge Function Secrets).

### 1. Додавання секретів через Supabase CLI

Виконайте команду у терміналі для встановлення ключа у вашому Supabase-проєкті:

```bash
# Встановлення API ключа зовнішнього постачальника спортивних даних
supabase secrets set FOOTBALL_API_KEY="ваш_секретний_api_ключ"

# Опціонально: кастомний базовий URL API (за замовчуванням https://api.football-data.org/v4/matches)
supabase secrets set FOOTBALL_API_URL="https://api.football-data.org/v4/matches"
```

Або введіть секрети у веб-панелі: **Supabase Dashboard → Project Settings → Edge Functions → Secrets**.

### 2. Локальне тестування функції

Для локального тестування створіть файл оточення для функцій (наприклад `supabase/.env.local` — не додавайте його в git):
```env
FOOTBALL_API_KEY=ваш_ключ
SUPABASE_URL=http://127.0.0.1:54321
SUPABASE_SERVICE_ROLE_KEY=ваш_service_role_key
```

Запустіть Edge Function локально:
```bash
supabase functions serve sync-results --env-file ./supabase/.env.local
```

Викличте функцію POST-запитом:
```bash
curl -i --location --request POST 'http://127.0.0.1:54321/functions/v1/sync-results' \
  --header 'Authorization: Bearer ВАШ_SERVICE_ROLE_KEY'
```

### 3. Деплой функції у хмару

```bash
supabase functions deploy sync-results
```

Після деплою функцію можна запускати періодично через розширення `pg_cron` (закоментований приклад розкладу наведено у файлі міграції `supabase/migrations/*_auto_results.sql`) або за допомогою зовнішнього планувальника (GitHub Actions, cron-job.org).
